# Phase 2C: Trip Enrichment — Design Spec

**Date:** 2026-04-16
**Status:** Approved
**Depends on:** Phase 2B (Intelligence Layer) — personality profile and corrections
**Goal:** Make saved trips rich enough that users open Sarthi on the ground instead of switching to Google.

---

## Overview

Phase 2A saves trips. Phase 2B makes them personal. Phase 2C makes them *useful on the ground* — every place has context, every location is one tap to navigate, users can edit their itinerary, ask questions about their trip, and learn basic local phrases.

---

## Features

### 1. Place Context Cards

Every place/activity in an itinerary and every restaurant in a food guide gets enriched context generated by AI.

#### 1.1 Context Card Fields

```typescript
{
  placeContext: {
    whySpecial: string,        // "One of the last living root bridges, grown over 150+ years by the Khasi tribe"
    bestTimeToVisit: string,   // "Early morning (7-9 AM) for best light and fewer crowds"
    suggestedDuration: string, // "2-3 hours including the hike down and back"
    insiderTips: string[],     // ["Wear grip shoes — steps are slippery", "Carry ₹20 for the entry fee"]
    whatToCarry: string[],     // ["Water bottle", "Rain jacket", "Cash (no UPI)"]
    nearbyAlternative?: string // "If too crowded, Mawryngkhew nearby has a single-root bridge with zero tourists"
  }
}
```

#### 1.2 Generation Strategy

Context cards are generated as part of the itinerary/food-guide AI call — not as separate calls. The itinerary prompt is extended to include `placeContext` in each activity. This avoids extra API calls.

For already-saved trips (created before Phase 2C), a one-time "Enrich Trip" button triggers a new AI call that adds context cards to the existing itinerary data.

#### 1.3 Schema Changes

Extend `itineraryActivitySchema` in `destination.schema.ts`:

```typescript
// Add to each activity in itinerary
placeContext: z.object({
  whySpecial: z.string(),
  bestTimeToVisit: z.string(),
  suggestedDuration: z.string(),
  insiderTips: z.array(z.string()),
  whatToCarry: z.array(z.string()),
  nearbyAlternative: z.string().optional(),
}).optional()
```

Similarly extend dish/restaurant schemas in the food guide with a lighter version:

```typescript
placeContext: z.object({
  bestTimeToVisit: z.string(),  // "Lunch hours (12-2 PM) for fresh preparation"
  insiderTips: z.array(z.string()),  // ["Ask for the thali — not on menu but best value", "Cash only"]
}).optional()
```

### 2. Smart Map Links

Every place, restaurant, and activity gets a `mapQuery` field — a pre-formatted string that opens Google Maps with directions.

#### 2.1 How It Works

The AI already generates place names and locations. We extend the prompt to include:

```typescript
{
  mapQuery: string  // "Living Root Bridge, Cherrapunji, Meghalaya"
}
```

The frontend constructs the Google Maps URL:
```
https://www.google.com/maps/search/?api=1&query={encodeURIComponent(mapQuery)}
```

No paid API needed. The backend just provides the search query string, the frontend opens the link.

#### 2.2 Schema Changes

Add `mapQuery: z.string()` to:
- `itineraryActivitySchema` (each activity)
- `dishSchema` (each must-try dish — the `where` field becomes the map query)
- `streetFoodItemSchema` (each street food item)

For food guide, the `where` field already exists. We add `mapQuery` as a more specific, navigable version (e.g., `where: "Trattoria, Police Bazaar"` → `mapQuery: "Trattoria Restaurant, Police Bazaar, Shillong, Meghalaya"`).

### 3. Editable Itinerary Locations

Users can customize their saved itinerary — swap places, remove activities, add new ones. Changes are stored and trigger corrections (Phase 2B).

#### 3.1 Edit Operations

| Operation | Endpoint | Description |
|---|---|---|
| Remove activity | `DELETE /saved-trips/:id/itinerary/day/:day/activity/:index` | Removes an activity, logs correction |
| Add activity | `POST /saved-trips/:id/itinerary/day/:day/activity` | Adds custom activity at position |
| Swap activity | `PUT /saved-trips/:id/itinerary/day/:day/activity/:index` | Replaces an activity |
| Reorder | `PATCH /saved-trips/:id/itinerary/day/:day/reorder` | Reorder activities within a day |
| AI suggest replacement | `POST /saved-trips/:id/itinerary/day/:day/activity/:index/suggest` | Ask AI for alternative, using personality + corrections |

#### 3.2 How Edits Work

The itinerary is stored as JSON in `SavedTrip.itineraryData`. Edit operations:

1. Read the current itinerary JSON
2. Apply the edit (remove/add/swap/reorder)
3. Write back the modified JSON
4. Log a `Correction` record (Phase 2B) capturing what changed and why

The "AI suggest replacement" endpoint sends the current itinerary context + personality profile + the activity being replaced to the AI, which returns 2-3 alternative activities with `personalMatch` signals.

#### 3.3 Data Model

No new Prisma models — edits modify `SavedTrip.itineraryData` JSON in place. Corrections are logged via the existing `Correction` model (Phase 2B).

New DTO:

```typescript
class AddActivityDto {
  time: string;          // "10:00 AM"
  activity: string;      // "Visit Wei Sawdong Waterfall"
  cost?: string;         // "₹50"
  position?: number;     // insert at index (default: append)
}
```

### 4. Local Phrasebook

AI-generated key phrases in the destination's local language. Generated once per destination and stored with the trip.

#### 4.1 Phrasebook Structure

```typescript
{
  phrasebook: {
    language: string,        // "Khasi"
    script?: string,         // "Latin" (if the language uses a non-obvious script)
    greeting: Phrase[],      // Hello, Thank you, Goodbye
    food: Phrase[],          // I want vegetarian food, How much?, This is delicious
    directions: Phrase[],    // Where is...?, How far?, Left/Right/Straight
    emergency: Phrase[],     // Help, Hospital, Police
    bargaining: Phrase[],    // Too expensive, Best price?, I'll take it
    culturalNotes: string[]  // "Khasi people appreciate if you try even basic greetings"
  }
}

interface Phrase {
  english: string;
  local: string;        // transliterated in Latin script for easy reading
  pronunciation: string; // phonetic guide: "Kum-no" 
}
```

#### 4.2 Generation

- **Trigger:** New endpoint `POST /saved-trips/:id/phrasebook` — generates phrasebook for the trip's destination
- **Stored in:** New nullable JSON field `phrasebookData` on `SavedTrip`
- **AI call:** Small, focused prompt — just the destination + state → phrasebook. One AI call per destination, cached.

#### 4.3 API Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/saved-trips/:id/phrasebook` | Yes | Generate phrasebook for trip destination |
| GET | `/saved-trips/:id/phrasebook` | Yes | Get stored phrasebook |

#### 4.4 Schema Changes

- Add `phrasebookData Json?` to `SavedTrip` model in Prisma
- New Zod schema `phrasebookSchema` in `src/ai/schemas/phrasebook.schema.ts`
- New prompt builder `buildPhrasebookPrompt` in `src/ai/prompts/phrasebook.prompt.ts`
- New AI service method `generatePhrasebook`

### 5. Trip Chat

Conversational AI that answers questions about the user's saved trip. Context-aware — it knows the itinerary, food guide, destination, and traveler personality.

#### 5.1 How It Works

User asks a question like:
- "Is there an ATM near Dawki?"
- "Can I swim at the Living Root Bridge?"
- "What should I wear at the monastery?"
- "Any good coffee shops in Shillong?"
- "Is Day 2 going to be physically tough for me?"

The backend takes the question, injects the full trip context (itinerary, food guide, destination, personality profile), and gets a conversational answer from the AI.

#### 5.2 Context Injection

The trip chat prompt includes:
- The full saved trip data (destination + itinerary + food guide) — summarized to fit context
- Traveler personality profile
- The current question
- Recent chat history (last 5 messages for continuity)

#### 5.3 Chat Storage

Chat messages are stored per trip — so the user can revisit questions they asked.

New Prisma model:

```
TripChatMessage
  id        String   @id @default(uuid())
  tripId    String   (FK -> SavedTrip)
  role      String   (enum: user/assistant)
  content   String
  createdAt DateTime @default(now())

  @@index([tripId, createdAt])
```

#### 5.4 API Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/saved-trips/:id/chat` | Yes | Send a question, get AI answer |
| GET | `/saved-trips/:id/chat` | Yes | Get chat history for trip |
| DELETE | `/saved-trips/:id/chat` | Yes | Clear chat history |

#### 5.5 Rate Limiting

Trip chat is the most API-intensive feature. Rate limit to 10 messages per trip per hour to stay within free tier limits.

## What This Phase Does NOT Include

- Real-time location features (Phase 2D)
- WebSocket connections (Phase 2D)
- Auto-replanning based on time/location (Phase 2D)
- Profile learning from patterns (Phase 2E)
- Offline download (Phase 2E)

- Unit tests for phrasebook generation (mock AI, verify schema)
- Unit tests for trip chat (mock AI, verify context injection, verify rate limiting)
- Controller tests for all new endpoints
- Integration test: edit itinerary → verify correction logged → new search uses correction
